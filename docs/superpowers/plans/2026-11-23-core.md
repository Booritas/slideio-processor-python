# slideio-processor Python core — Implementation Plan (plan 1 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `slideio-processor` wheel that loads SlideIO from the installed `slideio` package, runs a pipeline file against one slide from Python or a command line, with progress, cancellation and typed exceptions, built in CI on Windows, Linux and macOS.

**Architecture:** This repository holds `extern/slideio-processor` as a submodule, which carries `extern/slideio`. One CMake build compiles the processor's two shared libraries (`add_subdirectory`, test seams off) and a pybind11 module, `slideio_processor_native`. The Python package `slideio_processor` imports `slideio` first, checks versions, makes `slideio/core/libs` loadable, and only then imports the native module. A thin Python layer adds what C++ cannot: the background thread that makes Ctrl-C cancel a run, result objects, and the CLI.

**Tech Stack:** C++17, CMake ≥ 3.21, pybind11 3.1.0 (PyPI, build requirement), Conan 2, setuptools, pytest, Pillow (tests only), Python 3.12 for local and CI builds.

**Spec:** slideio-processor repository, `docs/superpowers/specs/2026-11-22-python-bindings-design.md` (also at `extern/slideio-processor/docs/superpowers/specs/` once Task 1 adds the submodule): §2 D1, D2, D4, §5.1, §5.2 "runs", §5.3 "Ctrl-C", §7, §9 D7. Plans 2–4 cover the rest of §5.

**Scope decisions:**
- **Moved to plan 3:** creating or opening a workspace from a `slideio.Scene` (D3). It has no use until stages and `StageRunner` are bound. The test carried from project 2 also needs a stage run to read pixels: drop every Python Slide/Scene object, then read through the handle. `SlideRun` takes paths.
- **Not in this plan:** `PipelineFile.from_workspace`, which needs a bound `Workspace`. Plan 3 adds it.
- **Not in this plan:** Linux and macOS wheel repair (`auditwheel`, `delocate`) and wheels for every Python version. Plan 4 does those. CI here installs the unrepaired wheel on the machine that built it.

## Global Constraints

- Python package name `slideio-processor`; import name `slideio_processor`; native module `slideio_processor_native`, installed in `slideio_processor/_libs/`.
- Version: MAJOR.MINOR from `set(projectVersion 0.1)` in `CMakeLists.txt`; the patch comes from the `CI_PIPELINE_IID` environment variable, defaulting to `0`. This is slideio-python's scheme.
- Dependencies: `slideio==2.11.1` (exact pin, D2) and `numpy`. Optional extra `pandas = ["pandas"]`. `requires-python = ">=3.9"`.
- Submodule `extern/slideio-processor` = `https://github.com/Booritas/slideio-processor.git` at `e6613a45961d147a6e28bfb80f83c8ecbfeb3811`. Its `extern/slideio` is `39ab9e24`, which is SlideIO v2.11.1.
- **D2:** the wheel ships no SlideIO library. `_libs/` holds exactly the native module and the processor's two shared libraries:
  - Windows: `slideio-processor-data.dll`, `slideio-processor-engine.dll`.
  - Linux and macOS: `libslideio-processor-data`, `libslideio-processor-engine` with the platform suffix.
  - No MSVC runtime DLLs: the `slideio` wheel ships those.
- **D2 loading:** `import slideio` first. On Windows, call `os.add_dll_directory(<slideio>/core/libs)` and keep the handle for the life of the process. On Linux the run path is `$ORIGIN:$ORIGIN/../../slideio/core/libs`; on macOS `@loader_path;@loader_path/../../slideio/core/libs`. This applies to the module and both processor libraries.
- **D2 version check:** before the native module is imported, compare the SlideIO version the package was built against with `slideio.get_version()`. On a mismatch raise `ImportError`, naming both versions and the `slideio==<built>` to install.
- Built with `SLIDEIO_PROCESSOR_TEST_SEAMS=OFF`: no test seams in a shipped wheel.
- **C-6 and the anti-goal:**
  - No exception message, CLI output or log line written by this package carries a path, a slide name or a value from the slide.
  - Messages come from the library, which already follows this rule. The Python layer adds only fixed text, and stage, layer, export and operation names.
- `SlideRun.slide_id` defaults to `""`, which is the library's default: exports carry no slide identifier unless the caller supplies one. This settles the "bindings set slideId by default" follow-up for `SlideRun`. Plan 3 applies the same rule to the writers it exposes.
- Tests run against the **installed wheel**, from a directory outside the checkout, so `import slideio_processor` never resolves to the source tree.
- Tests make their own slide: a 600×600 RGB PNG written with Pillow. It is opened by SlideIO's automatic driver choice (verified with slideio 2.11).
- Local environment: the conda env `slideio`, Python 3.12, at `%USERPROFILE%\anaconda3\envs\slideio\python.exe`, with conan 2.34 installed. Windows builds use Visual Studio 17 2022, x64, Release.

## Review Focus

1. **A second SlideIO copy in the process.** For example, CMake staging `slideio*.dll` next to the module, or a run path that finds a build-tree SlideIO first. Expect every loaded SlideIO image to come from `slideio/core/libs`. Test: Task 1 `test_one_slideio_copy`.
2. **The progress callback raises.** That includes a researcher's `print` to a closed stream. Expect the run to stop and the callback's exception to reach the caller, not a crash or a silent continue. Test: Task 3 `test_progress_exception_cancels_and_propagates`.
3. **Ctrl-C during a run.** Expect the run cancelled, no `.partial` file left, and `KeyboardInterrupt` raised. The process must not hang in a GIL-holding wait. Test: Task 3 `test_keyboard_interrupt_cancels`.
4. **A non-`ProcessorError` C++ exception reaches the binding.** Expect `InternalError`, whose message must not echo `what()`: a SlideIO message can hold a path. Test: Task 2 `test_unknown_native_exception_is_internal_without_text`, through a native helper compiled only into the test build (see Task 2).
5. **Paths in CLI errors.** A missing pipeline file, a missing slide, or a workspace bound to another slide. Expect a message and exit code 1 with no path anywhere in stdout or stderr. Test: Task 4 `test_cli_errors_name_no_path`.

  from slideio_processor import _loader
  from slideio_processor._libs import slideio_processor_native as native
  from support.loaded_libraries import loaded_library_paths

  def _slideio_libs():

      assert "2.11.1" in str(e.value) and "2.11.0" in str(e.value) and "slideio==2.11.1" in str(e.value)

      assert not ours & set(os.listdir(_slideio_libs()))

      theirs = {f.lower() for f in os.listdir(_slideio_libs())}
      loaded = [p for p in loaded_library_paths() if os.path.basename(p).lower() in theirs]
      assert loaded                               # SlideIO is loaded at all
      for p in loaded:

### Task 2: Exception hierarchy, PipelineFile and ExportSpec

**Files:**
- Create: `slideio_processor/errors.py`, `slideio_processor/pipeline_file.py`, `src/bindings.hpp`, `src/errors.cpp`, `src/pipeline_file.cpp`, `tests/test_errors.py`, `tests/test_pipeline_file.py`, `tests/data/three_stage.json`
- Modify: `src/module.cpp`, `CMakeLists.txt` (sources, and the test option below), `slideio_processor/__init__.py`

**Interfaces:**
- Consumes: Task 1's `load_native()` and module layout.
- Produces (all exported from `slideio_processor`):
  - **`ErrorCode(enum.IntEnum)`:** `INVALID_ARGUMENT=0, UNSUPPORTED_DATA_TYPE=1, CHANNEL_ARITY=2, STORE_FORMAT=3, STAGE=4, TILE=5, CANCELLED=6, IO=7, INTERNAL=8`. These are the C++ `ErrorCode` values in order.
  - **`ProcessorError(Exception)`:** attributes `code: ErrorCode`, `stage_name: str | None`, `operation_name: str | None`, `cause: str | None`, `tile: tuple[int, int] | None`. Each is None when the C++ value is null or empty, or when `hasTile()` is false.
  - **Subclasses, one per code:**

    | Class | Also a subclass of |
    |---|---|
    | `InvalidArgumentError` | `ValueError` |
    | `UnsupportedDataTypeError` | |
    | `ChannelArityError` | |
    | `StoreFormatError` | |
    | `StageError` | |
    | `TileError` | |
    | `CancelledError` | |
    | `IoError` | `OSError` |
    | `InternalError` | |

  - **`errors._from_native(code: int, message: str, stage: str, operation: str, cause: str, has_tile: bool, tile_x: int, tile_y: int) -> ProcessorError`:** the C++ translator calls it to build the exception.
  - **`ExportKind(enum.Enum)`:** `CSV`, `GEOJSON`, `LABEL_MASK`, `RASTER_TIFF`.
  - **`ExportSpec`:**
    - static constructors `csv(file, layer, measurements=())`, `geojson(file, layer)`, `label_mask(file, layer)`, `raster_tiff(file, raster)`
    - read-only `kind`, `file`, `layer` (None for raster exports), `raster` (None for object exports), `measurements: list[str]`
    - `__eq__` uses `equals`
  - **`PipelineFile`:**
    - `PipelineFile()`; static `from_json(text: str)` and `load(path: str | os.PathLike)`
    - `to_json() -> str`; `require(module: str) -> PipelineFile` and `add_export(spec: ExportSpec) -> PipelineFile`, both chainable
    - read-only `requires: list[str]`, `layer_names: list[str]`, `raster_names: list[str]`, `stage_names: list[str]`, `exports: list[ExportSpec]`
    - `__eq__` uses `equals`; `__repr__` gives the counts only.
  - **Native:** `void bindErrors(py::module_&)` registers one translator for `const slideio::processor::ProcessorError&`, then `std::bad_alloc` → `MemoryError`, then any other `std::exception` and `...` → `InternalError`. That last message is the fixed text `"an unexpected native error occurred"`, never `what()`.
